## The reading: METADATA only, and why that is sufficient here

The frozen recipe (`housekeeping_13aug_store_fingerprint.py`, re-derived by
`review15b_store_fingerprint.py`) computes two digests over the same file set, sorted by
POSIX-style relative path:

```
metadata digest = sha256 over "<relpath>|<size>|<mtime_ns>" lines
content  digest = sha256 over "<relpath>|<size>|<sha256 of the file's bytes>" lines
```

This session computes the FIRST line of that recipe, byte-for-byte, and skips the second, so it
opens no file under either root at all -- it only `stat`s them. `mtime_ns` is what makes that
sufficient: a file created, written, truncated, renamed or removed moves its size, its `mtime_ns`
or the file set itself, and all three are inside this digest. It is also seconds rather than
minutes and allocates nothing, which REVIEW_15B **R5** recorded as the practical constraint on
this machine.

The comparison target is REVIEW_15B PART 0's own published metadata digest.
