# The end-of-day summary, through the shipped CLI (chunk 14 · fix)

Generated by `docs/evidence/chunk14_end_of_day.sh` (committed beside this file, REVIEW_7 C3),
run on 2026-08-14 at commit `24f3cd3`.

The architect's 14-Aug-2026 ruling: *"the END-OF-DAY SUMMARY is a card line item and lands in
chunk 14 — routed to the phone via the sink at close, not only the terminal."*
`tests/test_telegram_sink.py` pins the message byte for byte on synthetic alerts. This is the
other half: the same code reached through `python -m acumen.run_screener` on a real symbol-day
out of the minute lake, so the alert list in the message is one the engine produced.

## What was run

```
PYTHONPATH=src python -m acumen.run_screener \
    --mode replay --day 2026-06-10 --symbols HDFCBANK,ICICIBANK \
    --telegram --recording-root <temp>
```

`--live-alerts` is deliberately **absent**, so the sink is in DRY RUN: it prints the message it
would have sent, reaches no transport, reads no `.env` key and opens no socket. Every byte the
run wrote went to a temp `--recording-root` outside both stores and outside the repository; the
minute lake was read in place, never linked and never copied (CLAUDE.md data-store safety).

## What it shows, and what it does not

1. **The route is real.** The summary is produced after `run_day()` returns — i.e. after
   `close_day()`'s 15:30 poll — from the alerts the sinks actually saw, and it is the last thing
   the morning does before the recording's path is printed.
2. **The alerts are the engine's.** `armed 11:15, trigger 11:30, exit 13:15` is HDFCBANK
   2026-06-10, the chunk-7 Rule-3 outside-bar golden that chunk 13's replay invariant walks
   (entry 740.95, SL 738.10, TP 749.50, qty 350, target on the 13:15 candle). ICICIBANK waited
   below the POC all day and produced no alert, so it is correctly absent from the summary.
3. **The dry-run gate holds end to end.** Two labels, from two sources — the sink's own
   `[DRY RUN -- not sent]` line and the message's own `[DRY RUN -- log only …]` line.
4. **No disclosed line, and that is correct.** This is a REPLAY. CONTEXT 4.7's disclosure is a
   statement about today's unverified feed and chunk 13's rule is that it appears on no replay
   alert; the summary reads its disclosure from the same session field, so it inherits that rule
   rather than restating it. A live morning's summary ends with the disclosed line — asserted in
   `test_the_END_OF_DAY_SUMMARY_is_SENT_ONCE_at_close_and_shown_here_VERBATIM`.
5. **What this run does NOT show:** a real send. No message was put on any phone here, no
   credential was read, and the `telegram-end-of-day-summary` mark is written only after a real
   send — so this recording carries none, which is why re-running the script prints the summary
   again rather than suppressing it. The send, the failure degradation and the resume guard are
   proved in `tests/test_telegram_sink.py`.
