# R1 FIX -- THE BARE-CLONE VERIFICATION

REVIEW_15B **R1**: three printable, operator-facing strings named `python -m acumen.<x>`, which
answers `No module named 'acumen'` on a tree with no editable install. The defect is invisible to
a green suite -- `pyproject.toml`'s `pythonpath = ["src"]` is PYTEST's path, not a hand-typed
subprocess's -- so the only verification that means anything is the one below: a **bare clone**,
`PYTHONPATH` **unset**, the command taken out of the string and run.

Generated by the committed `docs/evidence/r1_fix_bare_clone.sh`, which reproduces every line:

```
bash docs/evidence/r1_fix_bare_clone.sh <path-for-the-clone> <path-for-a-temp-cache>
```

**Nothing here fetches or writes.** The two commands whose real flags would touch the network or
the stores (`run_screener --refresh --allow-network` and the `ca_report` ingest) are resolved with
`--help`, which argparse answers before any body executes; the master fetch is run WITHOUT its
`--allow-network` opt-in against a brand-new empty temp directory. Flag-for-flag equivalence
between each dead form and its launcher is proved separately, per site, in
`tests/test_review15b_fix.py`, which parses every printed flag through that launcher's OWN parser
(each launcher forwards to the same `main`, so the argv is unchanged).

`fetch_instrument_master.py` ending `exit=1` on an EMPTY cache is REVIEW_15B **R4**'s disclosed
conditional (`return 0 if existing else 1`), not a failure: what is under test is that the command
is recognised and runs, and it prints its own *"Nothing was fetched and nothing was written."*
